Write a 6502 routine for the NES (NTSC) in ca65 syntax.

Routine label: `vblank_update`. It is called with JSR and must return with RTS.

Context: Your routine is called once per frame from the NMI handler of an NTSC NES game, with rendering on. The handler has already saved A, X and Y and does nothing else: it calls your routine with JSR and returns with RTI right after. All PPU and OAM DMA work must be finished inside vertical blank. Before returning, leave PPUCTRL at $80 and the scroll at X=0, Y=0, so the next frame is drawn from nametable $2000 unscrolled.

Task: First do the OAM DMA from page $02 (the sprite table at $0200-$02FF). Then copy the 256 bytes at $0300-$03FF to consecutive PPU addresses, starting at the address in zero page $00 (low byte) and $01 (high byte). The destination is always inside nametable 0 and the 256 bytes end before $2400.

Rules:
- You may change A, X and Y, use zero page $10-$1F as scratch, and use the stack. Do not write any other RAM.
- The code runs from ROM, so no self-modifying code. Tables in ROM are fine (after the code, with .byte).
- Your file is included into the harness's CODE segment: no .segment, .org, header or vectors. Prefix your labels with `vblank_update_` or use @cheap local labels.
